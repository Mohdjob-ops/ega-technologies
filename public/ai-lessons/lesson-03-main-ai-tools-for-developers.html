Technical Explanation — English

Many AI services are available to developers, but they do not all solve the same problem.

Some AI products are designed to work beside the developer inside a code editor.

Other products attempt to generate most of an application automatically from a short description.

This EGA course focuses mainly on tools that help developers improve their normal coding workflow:

  • GitHub Copilot
  • Cursor
  • ChatGPT

These tools can help a developer work faster, understand code, explore solutions, and improve existing work.

However, the developer must remain responsible for reviewing, testing, and approving the final result.

Two Approaches to AI Development

AI development services can be placed into two broad groups.

Approach Main Idea Developer Role
AI-assisted development AI helps the developer write, understand, edit, and review code. The developer stays actively involved.
AI-generated applications AI attempts to create large parts of an application from instructions. The developer reviews and adjusts the generated result.

AI-Assisted Development

AI-assisted development means using AI while still controlling the programming process.

The developer may ask AI to:

  • Complete an unfinished line of code.
  • Explain an unfamiliar function.
  • Suggest a better solution.
  • Find a possible mistake.
  • Improve code organization.
  • Create documentation.
  • Help prepare tests.

This method combines human knowledge with AI speed.

AI Application Builders

Some services try to build complete applications from natural-language instructions.

Examples of services in this wider category may include tools such as Replit, Bolt, v0, and similar platforms.

A user may enter an instruction such as:

Create a student-registration website with a form, dashboard, payment page, and database.

The service may attempt to generate:

  • Page layouts
  • User-interface components
  • Application logic
  • Database connections
  • Deployment settings

These services may be helpful for quick prototypes, experiments, and simple applications.

They may become more difficult to manage when a project requires detailed business rules, security, payments, database permissions, or several connected features.

Why Complex Projects Require More Control

A generated application can look correct while still containing serious hidden problems.

Possible problems include:

  • Incorrect database permissions
  • Weak authentication
  • Missing error handling
  • Incorrect payment calculations
  • Duplicate records
  • Broken mobile layouts
  • Code that is difficult to maintain
  • Features that do not match the real requirements

EGA Development Principle

The more important the application becomes, the more carefully the developer must understand and verify every part of it.

Why GitHub Copilot Is a Main Focus

GitHub Copilot can work directly inside supported code editors.

It can examine nearby code and suggest what the developer may want to write next.

GitHub Copilot may help with:

  • Code completion
  • Repeated code patterns
  • Function suggestions
  • Code explanations
  • Test suggestions
  • Documentation

The developer can accept, modify, or reject every suggestion.

Why Cursor Is a Main Focus

Cursor is a code editor built around AI-assisted development.

Its AI tools can work with:

  • One selected line
  • A complete file
  • Several related files
  • A larger project structure
  • Refactoring requests
  • Questions about existing code

This deeper project context can be useful when a coding task involves more than one small code example.

Why ChatGPT Is Included

ChatGPT is useful for development tasks that are not limited to editing one code file.

A developer may use it for:

  • Planning a project
  • Learning technical concepts
  • Comparing possible solutions
  • Understanding an error message
  • Preparing documentation
  • Discussing database structure
  • Creating exercises and learning materials

ChatGPT can be helpful when the developer needs a broad discussion before making a technical decision.

Choosing a Tool Based on the Task

Development Task Possible Tool
Completing code while typing GitHub Copilot
Updating several connected files Cursor
Planning project architecture ChatGPT or Cursor
Creating a quick prototype An AI application builder
Checking production security Developer knowledge supported by AI

No single tool is best for every situation.

A developer should choose based on the task, project size, required control, and possible risks.

A Responsible AI Workflow

  1. Understand the problem.
  2. Choose the most suitable tool.
  3. Give clear instructions and useful context.
  4. Read the generated result.
  5. Check whether it matches the requirements.
  6. Test the code.
  7. Correct errors and security problems.
  8. Save only the verified version.

Efficiency means reducing unnecessary work without removing careful technical review.

HTML Learning in This Lesson

This lesson uses real HTML elements so that students can learn both AI development and webpage structure.

Important elements used in this lesson include:

  • <blockquote>
  • <article>
  • <table>
  • <thead>
  • <tbody>
  • <tr>
  • <th>
  • <td>

The Blockquote Element

The <blockquote> element displays a longer quotation or an important statement separately from the surrounding paragraphs.

HTML Code 

<blockquote>
    AI should support the developer's knowledge.
</blockquote>

Browser Output

AI should support the developer's knowledge.
  • <blockquote> is the opening tag.
  • The sentence is the content.
  • </blockquote> is the closing tag.

The Article Element

The <article> element groups complete content that can make sense independently.

HTML Code 

<article>

    <h3>Important Principle</h3>

    <p>
        Developers must test AI-generated code.
    </p>

</article>

The opening tag is <article>.

The closing tag is </article>.

It is useful for an independent explanation, lesson, article, news item, or blog post.

HTML Table Structure

A table organizes related information into rows and columns. 

<table border="1">

    <thead>

        <tr>
            <th>Tool</th>
            <th>Purpose</th>
        </tr>

    </thead>

    <tbody>

        <tr>
            <td>Cursor</td>
            <td>AI-supported code editing</td>
        </tr>

    </tbody>

</table>
  • <table> creates the complete table.
  • <thead> contains the table headings.
  • <tbody> contains the main table information.
  • <tr> creates a row.
  • <th> creates a heading cell.
  • <td> creates a normal data cell.

Important Rules

  • Choose an AI tool according to the task.
  • Do not assume that one tool can solve every problem.
  • Review generated code before using it.
  • Test databases, payments, forms, and authentication.
  • Do not use code that you do not understand.
  • Keep control of the final development decision.
  • Never share passwords, private keys, or secret credentials.
  • Use AI to strengthen learning, not avoid learning.

Common Beginner Mistakes

  • Accepting every AI suggestion automatically
  • Believing a generated application is always complete
  • Failing to test forms and database operations
  • Choosing a popular tool that does not fit the task
  • Giving instructions without enough context
  • Ignoring security and maintenance
  • Depending on AI without learning programming
  • Using an incorrect image path

GAL — General Analogy Learning — English

Imagine that a doctor works in a modern hospital.

The doctor may use:

  • A blood-pressure machine
  • A laboratory computer
  • A medical scanner
  • A digital patient-record system

These tools provide information and make work faster.

However, the machines do not replace the doctor's knowledge and responsibility.

AI development tools work in the same way.

  • GitHub Copilot helps during coding.
  • Cursor helps with connected project files.
  • ChatGPT helps with planning and explanations.
  • Application builders may quickly produce a prototype.

The developer, like the doctor, must review the information and make the final decision.
