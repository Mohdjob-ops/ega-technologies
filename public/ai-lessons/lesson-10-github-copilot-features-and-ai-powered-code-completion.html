EGA AI DEVELOPER COURSE — LESSON 10

GitHub Copilot Features and AI-Powered Code Completion

Learn how GitHub Copilot can suggest code, predict your next edit, offer alternative completions, and use comments as instructions.

🎯 Learning Objectives

By the end of this lesson, you should be able to:
  • Explain AI-powered code completion.
  • Accept Copilot suggestions with the Tab key.
  • Understand Next Edit Suggestions.
  • View alternative AI suggestions.
  • Accept only part of a suggestion when needed.
  • Use comments as simple prompts for Copilot.
  • Turn Copilot suggestions on or off.

1. What Does GitHub Copilot Give Us?

GitHub Copilot is more than a tool that completes a single line of code. It can assist while you type, predict likely changes elsewhere in your project, suggest different solutions, and generate code from natural-language comments.

One of its oldest and most familiar features is AI-powered autocompletion. Copilot watches the code and context around your cursor and predicts what you may want to type next.

Copilot suggestions are suggestions only. The developer remains responsible for reviewing, testing, and deciding whether to accept them.

2. AI-Powered Autocompletion

Imagine you begin writing a Python variable: 

name =

Copilot may automatically display a possible value or completion. The suggestion is normally shown in lighter text before you accept it.

If the suggestion is useful, you can usually press: 

Tab

to accept it.

If you do not like the suggestion, you can ignore it and continue typing your own code.

3. Copilot Can Predict More Than One Line

Modern GitHub Copilot can also make Next Edit Suggestions.

This means that after you change one part of your code, Copilot may predict another change that you are likely to make somewhere else.

For example, if you rename a function, Copilot may recognize that another line still uses the old name and suggest updating it. 

def combine_names(first, last):
    return first + " " + last

full_name = combine_names("Ayan", "Ali")

If you rename combine_names, Copilot may anticipate that the function call also needs to change.

4. Next Edit Suggestions

Next Edit Suggestions try to anticipate what you are likely to edit after your current change.

This can be useful during:

  • Function renaming
  • Variable renaming
  • Repeated code changes
  • Refactoring
  • Updating related code

In supported editors, these suggestions may also be accepted with Tab.

5. Turning Suggestions On or Off

GitHub Copilot does not have to remain active everywhere. Depending on your editor and Copilot version, you can control different types of suggestions.

You may be able to:

  • Turn off Next Edit Suggestions.
  • Disable AI suggestions completely.
  • Disable Copilot for a specific file.
  • Disable it for certain file types or languages.
The exact menu names may change as GitHub Copilot and Visual Studio Code are updated. Focus on understanding the feature rather than memorizing one button location.

6. Viewing Alternative Suggestions

You do not always have to accept the first suggestion Copilot gives you.

In some situations, Copilot can provide multiple alternatives. For example, after starting: 

person =

one suggestion might be a simple string: 

person = "Mohammed"

while another might create a dictionary: 

person = {
    "name": "Mohammed",
    "role": "Developer"
}

You can inspect available alternatives and choose the one that best matches your intention.

7. Accepting Only Part of a Suggestion

Sometimes an AI suggestion is partly correct but contains more code than you want.

Copilot may allow you to accept a suggestion gradually, such as accepting only the next word or part of the proposed code.

This gives you more control than blindly accepting a complete AI response.

A good developer does not accept suggestions automatically. Read the proposed code first.

8. Using Comments as Prompts

One particularly useful Copilot technique is writing a comment that describes what you want.

Example: 

# Function that combines two strings

Copilot may then suggest something similar to: 

def combine_strings(first, second):
    return first + second

The comment works like a small natural-language prompt.

After the code has been generated and reviewed, you may keep the comment if it is useful documentation or remove it if it is no longer needed.

9. Practical Example

Suppose you want a function that creates a student's full name. Start with a clear comment: 

# Function that combines first name and last name

Copilot may suggest: 

def full_name(first_name, last_name):
    return first_name + " " + last_name

student = full_name("Ayan", "Ahmed")
print(student)

Output

Ayan Ahmed

10. English Technical Summary

  • GitHub Copilot provides AI-powered code completion.
  • Tab can be used to accept many inline suggestions.
  • Next Edit Suggestions can predict related changes elsewhere.
  • Copilot may offer multiple possible completions.
  • Developers can sometimes accept suggestions piece by piece.
  • Natural-language comments can act as prompts for code generation.
  • Copilot suggestions should always be reviewed and tested.

12. Rules for Using Copilot

  1. Read every important suggestion before accepting it.
  2. Understand what generated code does.
  3. Test generated code.
  4. Do not paste passwords, secret keys, or private data into prompts.
  5. Use AI to assist learning, not replace understanding.
  6. Change or reject suggestions that do not match your goal.

13. Common Mistakes

  • Accepting every suggestion without reading it.
  • Assuming Copilot-generated code is always correct.
  • Using unclear comments and expecting perfect results.
  • Forgetting to test generated code.
  • Sharing sensitive information unnecessarily.
  • Becoming dependent on Copilot without learning the programming concepts.
